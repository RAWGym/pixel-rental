# Pixel Rental

Сайт и приложение проката фото- и видеотехники **Pixel Rental** (Алматы, Астана): каталог из 241 позиции, онлайн-бронь с проверкой доступности по датам, готовые комплекты под съёмку, личный кабинет с верификацией по удостоверению и админка с дашбордом для владельца, менеджеров, склада и бухгалтерии.

Один код на React + TypeScript + Tailwind работает в трёх видах:

| Где | Как собирается | Что получается |
|---|---|---|
| **Сайт и PWA** (Vercel) | `npm run build:web` → `dist-web/` | обычный сайт с чанками, фото отдельными файлами, офлайн через service worker, установка на экран «Домой» |
| **Приложение** (Expo, отдельный репозиторий-обёртка) | `npm run build` → `dist/index.html` | один HTML-файл со всем внутри, встраивается в WebView |
| **Разработка** | `npm run dev` | Vite dev-сервер |

## Быстрый старт

```bash
npm ci
npm run dev          # http://localhost:5173
```

Без настроек приложение работает в **демо-режиме**: данные (каталог, брони, клиенты) создаются в браузере и хранятся в `localStorage`. В профиле есть «Демо-сценарий» для презентаций.

- Клиентская часть: `/`
- Админка: `/admin` (или `#admin`). Демо-PIN: владелец `0000`, менеджеры `1111` / `2222`, склад `3333`, бухгалтер `4444`.

## Сборка сайта

```bash
npm run build:web    # раскладывает фото, проверяет типы, собирает dist-web/, готовит sw.js
npm run preview:web  # http://localhost:4173: проверить сборку локально
```

`build:web` делает:
1. `scripts/split-photos.mjs`: миниатюры товаров из `src/data/photoData.ts` → `public/photos/*.webp`, индекс путей → `src/data/photoIndex.ts`;
2. `tsc -b`: проверка типов;
3. `vite build --mode web`: сборка в `dist-web/` (админка и графики: отдельный чанк, грузится только сотрудникам);
4. `scripts/post-web.mjs`: версия кэша и список офлайн-файлов в `sw.js`.

## Деплой на Vercel

Настройки уже лежат в `vercel.json` (команда сборки, папка `dist-web`, SPA-маршруты, кэш: `/assets` и `/photos`: навсегда, `sw.js` и `index.html`: без кэша, заголовки безопасности).

**Через сайт Vercel:** Add New → Project → импортировать этот репозиторий → Deploy. Фреймворк выбирать не нужно.

**Через CLI:**
```bash
npm i -g vercel
vercel login
vercel          # превью
vercel --prod   # продакшн
```

Переменные окружения (Vercel → Settings → Environment Variables): см. `.env.example`.

## База данных (Supabase)

Слой данных вынесен в `src/data/api.ts` (интерфейс `PixelApi`). Сейчас работает `LocalAdapter` (браузер). Подключение Supabase:

1. Создать проект на supabase.com.
2. Применить миграции из `supabase/migrations/` (SQL Editor или `supabase db push`).
3. В Vercel задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (публичный anon/publishable ключ). **Service role / secret key в браузер и в репозиторий не кладём.**
4. Без этих переменных приложение остаётся в демо-режиме.

## Структура

```
src/
  client/      экраны клиента: главная, каталог, товар, корзина, оформление, брони, профиль, вход и верификация
  admin/       админка: дашборд, брони, шахматка, товары, заявки, клиенты, сотрудники, настройки, журнал
  data/        типы, сид демо-данных, сценарии съёмок, слой данных (api.ts), фото
  lib/         доступность, цены, форматирование, PWA, устройство
  store/       состояние (zustand) и навигация
  ui/          общие компоненты
public/        иконки, manifest, sw.js, offline.html, фото для сайта
scripts/       подготовка фото и сборки
```

## Устройства

- Мобильный вид (< 1024 px): как приложение: нижняя навигация, жесты, safe-area.
- От 1024 px: сайт: верхнее меню, фильтры каталога слева, футер.
- Слабые устройства (≤ 4 ядер, ≤ 3 ГБ, режим экономии трафика) получают облегчённые анимации; системная настройка «уменьшить движение» отключает их.
